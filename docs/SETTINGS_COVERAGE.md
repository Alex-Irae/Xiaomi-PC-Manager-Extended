# Settings coverage

Current integration, 2026-09-27. The larger manager now uses this app's own categorized English web UI. `Services/ManagerSettings.cs` exposes a bounded catalog backed by XiControl controller callbacks, guards and the shared configuration. Imported native settings code remains as vendor implementation/reference, but there is no separate user-facing Advanced / More settings destination. See `RUNTIME_TEST_REPORT.md` for tests, failures and version-specific evidence.

The popup retains brightness, modes, Travel/Cancel, input toggles, auto refresh, Stay awake and lower app links. Its read-only care summary opens the larger Battery page. Customization belongs to the larger Settings page. `www/quick-tools.js` remains the developer extension list for future search/translation native capabilities; user app links do not replace those integrations.

The catalog rejects unknown setting IDs, numeric enum substitutions, unlisted choices, nonfinite/out-of-range numbers, duplicate curve lux points and duplicate or unknown key codes. Haptic strength uses the actual XiControl presets. A saved policy request does not prove a deferred hardware operation succeeded; actual readbacks/errors remain necessary.

## OEM-only functionality

Content-aware AI brightness, OEM eye-protection/color profiles, five-finger XiaoAI gestures, meeting effects, OEM cleanup/boost engines, Store/account and other proprietary settings remain in the original Xiaomi manager. The Toolbox gives explicit access and destination guidance. They are not represented as independent working toggles here. Interconnect/sharing is deliberately excluded by the user's newer request, which takes precedence over the older attachment.

Driver scanning uses the inspected `--scan_driver` contract. Its launch request has been exercised, but completed scan/exact page is unconfirmed. No verified standalone OEM driver host exists, and this app does not install drivers. Ambient-light brightness and firm-press actions use XiControl semantics, which can differ from Xiaomi's AI features.

## Optional API

The original command allowlist and bearer-token mechanism are preserved. Local/LAN binding, port, command permissions and charge-limit webhook are exposed in Settings. The body ceiling is 4096 bytes, including chunked input, with a ten-second read/write deadline. Token hashes/settings use administrator/SYSTEM ACLs in this app's own ProgramData directory. API replies accept queued operations before completion; LAN/firewall, webhooks and end-to-end network behavior have not been accepted in these device tests.

Build/static checks verify all 61 required imported callbacks and the new catalog's AppConfig names. Frontend fixtures verify production event handlers, slider coalescing and ETA edge cases. These checks complement device runs; they do not certify physical gestures, all firmware keys, third-party launch broker compatibility or every policy over sleep/resume.

Keyboard app assignments live in root `KeyAppLinks`, separate from popup `QuickLinks`. The router accepts only listed page names. App selection validates the key slot before opening a dialog; unknown/unassigned app slots are refused. Native selection and Explorer launch compatibility remain unverified end to end. The user confirmed the prior Mi, Settings/F9 and AI routing responds physically. Current defaults reserve AI/F7 for the dynamically resolved XiaoAI, open Windows Settings with F9 and open This PC from the popup gear; choosing a new app is a separate acceptance check.

Category defaults are exposed inside each catalog row's help tooltip and validated against the same bounds/types/choices as user input. Reset buttons invoke controller callbacks and category-specific main controls, with explicit partial-failure messages. The catalog now also includes clean-exit automatic restart and OEM session cleanup. Other-model compatibility, optical OSD delivery and a real Windows reboot remain separate from callback tests.

## Manual display override and shortcut limits

The deprecated HoldRefreshRate field remains readable for old configurations but no longer enforces the screen rate. Power status events on the same source, manual display changes, same-source resume and startup do not apply the automatic rate again. A delayed resume check observes the power source, not the display rate. Explicit editing/enabling of automatic rules applies the selected rule once. Windows persists manual selections through its display registry API; a real reboot has not been certified.

When a supported firmware event is received, the host records Fn+K mode readback without switching twice and routes the refresh-rate event through the original display cycle. Custom Windows shortcuts accept up to 16 unique Ctrl/Alt/Shift/Win chords and listed manager pages/device actions or saved app links. Unsupported keys, duplicates, unassigned apps and OS conflicts are refused. A failed registration restores the previous binding set. Physical Fn event delivery remains model-specific.

Keyboard category reset clears registered custom Windows shortcuts; Settings reset restores Xiaomi OSD style, blue/light appearance and compact 90% panel defaults. Profile and app assets are retained. Close always hides to tray, independent of the compatibility CloseToTray field.
